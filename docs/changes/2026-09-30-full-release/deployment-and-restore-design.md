# Exact-image deployment and rollback rehearsal

This is an operations design, not an executed change. The 2026-09-30 [read-only preflight](server-preflight.md) found one running `api` Compose service, launched from mutable `latest` with source revision `473a39bee299f3df4c7fdcf6f45502f880a9bd8b`. Its local image ID is `sha256:d7fe5a48d8b805ac33eaa7ea50f27031c8dde2baf7df4b9982ffef0b894b96b2`; this is **not** a GHCR manifest digest. `TestMode=true`, Apple is set to `Sandbox`, and the deployment directory was masked. The current manual deploy job builds and pushes, then pulls mutable `latest` and runs `docker compose up -d`; a concurrent push or rerun can change which image `latest` means.

## Minimal workflow change before deployment

1. Give the existing build/push step an ID and pass its published **manifest digest** to the deploy job. The deployment target is `ghcr.io/dostonelmurodov/mavrylo@sha256:<that digest>`, tied to the selected workflow ref. Reject an empty or malformed digest. The current source revision label must match the selected commit after startup. A SHA tag alone is insufficient because a rerun can replace it.
2. On the host, retain the current container's exact local image ID and discover any existing registry `RepoDigest` through read-only inspection before pulling. A local rollback tag may protect that image from pruning; record the old source revision and image ID. Do not mistake the image ID for a registry digest.
3. Authenticate to GHCR with the token on SSH stdin, not interpolated into the remote shell command or logs. Use the existing SSH secrets and checked-in deployment script. Keep the deployment path as a validated, quoted argument. Pull the exact digest; make Compose use that digest through a small durable override or an atomically updated image reference, rather than pulling `latest`. Validate the rendered `api` image reference without printing environment values. Recreate only `api` with Compose, then verify container state, image ID, source revision, and loopback `/health`. A health response alone does not prove the paid-access contract.
4. Record the prior Compose image reference and retain its image locally for a controlled rollback. Do not run `docker compose logs`, raw `config`, raw `inspect`, or `api.env` into GitHub Actions output. Log only bounded status and approved metadata.

## Data safety and rehearsal

Before changing the live container, use approved server-side database access to produce a private, time-stamped `pg_dump` custom-format backup. Never print its connection credentials or contents. Verify nonzero file size, checksum, `pg_restore --list`, ownership/mode, and storage capacity. Restore it to a **separate temporary database**, then run the exact candidate API image against that copy so its automatic startup migrations execute there. Confirm migration success, required tables/columns, aggregate subscription inventory, and a small set of no-provider contract checks. Capture a second backup after the rehearsal if the live database changes meanwhile.

For cutover, arrange a short write pause or equivalent maintenance gate, take and verify a fresh backup at that boundary, then deploy the digest-pinned image. Writes after the backup make a full database restore lossy; the rollback decision must account for that interval. Rehearse both the restore command on the isolated copy and return to the retained image with the schema state it can actually read. If old code cannot safely run on the migrated schema, keep service restricted and move forward with a corrected image or a reviewed restore plan. The old image must not automatically be restored to public traffic if it reopens the paid-access defects.

## Decisions still needed from evidence

- Choose the target environment and its separate database. The observed target trusts Apple `Sandbox`; do not relabel its shared dataset as Production. Resolve `ASPNETCORE_ENVIRONMENT`, effective config sources, `TestMode=false`, real `AppAppleId`, operation quotas, and cumulative AI spend allowances before paid access is enabled. Missing environment values in the preflight log do not prove they are absent from every config source.
- Use the read-only database inventory and restoration rehearsal to determine legacy purchase reconciliation work. Preserve raw identifiers and receipts in private records only; report aggregate counts.
- Confirm the deployment user can read the database credentials and create/restore backups in the intended isolated location. Host `pg_dump`/`psql` and `sudo -n -l` availability do not prove those specific permissions.
- Select a rollback window and acceptable write pause after rehearsing against the actual old schema and candidate image. Do not infer safe rollback from a passing health check.
