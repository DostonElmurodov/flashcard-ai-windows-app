# Encrypted backup and pinned image export implementation

Status: source frozen for fresh review at backend HEAD `3716736cccbf5102eed60b8428240c2ab454ce8e`. No export workflow, SSH transfer, GHCR pull, artifact upload, Docker save, Git mutation, decryption, or restore was performed by this task.

The manual `export-backup` job accepts the exact completed backup ID, its expected plaintext SHA-256, and a base64 PEM **public** X.509 recipient certificate. It runs focused tests on Ubuntu before SSH, then pipes the reviewed helper source through the existing SSH channel. The server helper checks the canonical deployment directory and private backup directory, validates one complete archive and its manifest by ID, size, ownership, 0600/0700 modes, and SHA-256, and refuses archives larger than 64 MiB. The helper holds the verified archive open by file descriptor through encryption and rechecks its SHA-256 afterward. It accepts only a currently valid RSA 3072/4096 certificate and runs bounded OpenSSL CMS encryption using AES-256-CBC and RSA-OAEP with SHA-256. OpenSSL errors are suppressed. Ciphertext is written to a private 0600 file with a size limit; existing backups and incomplete files are left untouched. The remote process sends only ciphertext to stdout and fixed metadata to stderr. The runner checks that the received ciphertext is nonempty, within the limit, and parses as CMS DER, then uploads only the `.cms` ciphertext for one day. The user's recipient private key is never a workflow input or present on the server.

The manual `export-image` job uses `GITHUB_TOKEN` with `packages: read`, without SSH or a build/deploy dependency. It accepts an exact `sha256:<64>` GHCR digest and 40-character source revision for the fixed `dostonelmurodov/mavrylo` repository. It pulls the exact digest, verifies that the inspected image includes that digest and matching OCI revision label, captures the immutable config image ID, saves that image ID to a gzip archive, and uploads only the compressed archive plus safe provenance JSON for one day. The JSON keys are exactly `registry_digest`, `source_revision`, `image_id`, `archive_sha256`, and positive integer `archive_bytes`. The workflow logs those same pins. Docker credentials stay in the ephemeral runner's private Docker config directory and are not uploaded. This mode does not rebuild an image or move the mutable `latest` tag.
