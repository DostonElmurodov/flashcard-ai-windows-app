## Ruled conflicts and exact security limits

- Original strict-key recovery debate is closed for ordinary mobile restore. Original installation key is retained only as strong first-desktop-claim authority. No recovery-key product is introduced. Full key loss still permits normal mobile restore; exceptional first Windows claim uses the separate explicit error/support path.
- Registration must not trust caller DeviceUuid or reset key state. B1 safe assertion stays. Existing IAP receipt-transfer and first-desktop copied-JWS tests retain 403/no-mutation semantics; their genuine positive fixtures must establish the new server owner/token context rather than UUID equality.
- Apple events/refresh are state-only, not owner/key/account enrollment. Existing Upsert's two DeviceUuid relink paths must disappear. Account deletion preserves purchase/grant/claim tombstone and usage lineage while deleting/revoking private account scope as before.
- `ToDeviceEntitlement`'s account_required projection conflicts with independent mobile grants. Remove it for proven mobile access; an Owl session remains necessary for its private data and Windows rights. Logout is not a fresh operation or money budget.
- AppTransaction wire fields differ from transaction fields: receiptType/receiptCreationDate and production appAppleId must be checked. Current Apple SDK documents appTransactionID back-deployment, so an iOS18.4-only restore requirement is wrong for this iOS17 app. Signed optional-ID absence takes the paired-device legacy route; missing mandatory device evidence does not silently fall back to copied JWS.
- Family Sharing/old/external purchase may lack appAccountToken. Allow valid mobile/lifecycle verification; never fabricate token or give first desktop owner proof. App/purchase account mismatch, Family Sharing recipient metadata and historical local-device evidence need physical validation. They are not proven by synthetic tests.
- The full Apple envelope is not cryptographically bound to a new App Attest key. Complete capture/relay can still acquire bounded mobile access/deplete the same allowance; no owner rotation, desktop claim or private-data authority follows. No arbitrary freshness window is promoted to proof. A copied purchase JWS alone remains insufficient.
- Current entitlements omit expired/revoked products. 3B must perform bounded latest historical discovery for the two allowed products, preserve sticky paid history, and distinguish empty discovery from outage. Restore cannot convert recognized expired paid history into a fresh free quota/trial.
- D2 values and live money budget are unapproved.6A uses synthetic limits/configuration validation, preserves legacy day+minute history and shares the same selected purchase/actually-linked account counters. Different authenticated accounts remain independent even if a phone/anonymous owner reaches both; an owner credential is not a universal quota ancestor. Original pre-purchase usage attribution differs from unrelated free use on a newly restoring phone. Free-minute configuration is optional, not another required product decision. Task7 aggregate guest includes anonymous paid mobile; cumulative money/per-provider-attempt behavior is unchanged.
- Retained true-free ordering is a separate real identity conflict: backend arrival timestamp/server row ID and semantic uniqueness differ from iOS `(created_at,id)` and duplicate IDs.6B adds minimal client creation metadata, exact ID/index handling and metadata-only reconciliation within the existing authenticated saved library. Ten remains once across that library's collections/languages; it is not a hidden aggregate over other phones/private libraries. No new Library/word-registry framework. Server random ordering, deleting excess rows, fake acknowledgments and semantic deletion of another card remain unacceptable.
- Legacy data may be ambiguous because current UUID associations were client-supplied/overwritten. Preserve it as unproven; require sanitized-copy migration inventory and accounting reconciliation before cutover. No new verified owner is inferred solely from the old UUID. Do not hide unreconciled counters by setting them to zero.
