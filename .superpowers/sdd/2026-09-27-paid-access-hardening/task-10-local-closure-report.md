## Provenance and selected behavior

The marker is an exact authenticated device-key restriction, never purchase ownership or paid-history proof. The present claim transaction writes it true in `AccountEntitlementService.ClaimAsync`; `DeviceContextService.MarkClaimedPurchaseAsync` still writes true but has no current caller. The migration that introduced it defaults false and does not derive it from UUID. Historical feature base `473a39bee299f3df4c7fdcf6f45502f880a9bd8b` additionally called `FindForDeviceAsync(device.DeviceUuid)` and automatically marked the requesting key when the UUID-selected purchase was claimed. A shared UUID could therefore have marked an unrelated key. This is a possible false positive from source provenance, not a claim about production rows.

`DeviceContextService` now carries `RequiresSubscriptionReconciliation` when the exact marker is true and neither an applicable owner/mobile candidate nor an active independently authenticated account fallback resolves it. The property does not change entitlement or set `WasEverPaid`. Token and entitlement return `503 subscription_reconciliation_required`; AI checks it after device JWT, assertion and input protections, before word/quota/provider work. New device-word mutation and public publication are closed while unresolved. Context resolution remains usable by credential and Restore paths; no global exception blocks proof acquisition. Read/count/order and exact deletion paths remain available. Applicable finite grants retain inactive/expired results through ordinary selection. The marker is not cleared on Restore, logout or outage.

Simplify review after the policy iteration kept one context predicate shared by the commercial routes, reused the existing 503 code and ordinary entitlement selection, and removed the need for any new marker table, migration, global context exception or destructive clear. The later test iterations only corrected fixture setup/state expectations and added exact preservation snapshots; no extra product branch was needed.

`docs/paid-access-policy.md` now separates the approved ten-active-card content policy and metadata-only retention from still-unapproved daily/minute AI limits and monetary budgets, and records the marker recovery contract. It also updates older B4 prose to reflect accepted stable purchase subjects and fail-closed historical accounting; it leaves unknown-person/global guest identity as an external limit. No numeric AI commercial setting changed.
