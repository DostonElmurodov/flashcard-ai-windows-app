## HTTP boundary check during Mac CI preparation
- Program.cs uses plain AddHttpClient; both provider services call CreateClient() with no configured provider-specific primary handler. No Polly/resilience/HTTP retry registration was found in the current source search. Fallback remains the explicitly implemented application-level second attempt; this does not prove all transport behavior is disabled.
- OpenAI currently uses PostAsync and Gemini uses SendAsync(req, ct), with the default completion mode buffering content before the subsequent ReadAsStreamAsync. A response cap applied only to that later stream would therefore be too late to bound buffering. Use an explicitly bounded buffered approach or ResponseHeadersRead plus bounded body consumption; do not claim a late parser-length check bounds network memory.
- [Microsoft HttpCompletionOption](https://learn.microsoft.com/en-us/dotnet/api/system.net.http.httpcompletionoption?view=net-10.0) documents that ResponseHeadersRead makes HttpClient.Timeout stop at headers and bypasses MaxResponseContentBufferSize. Any streaming implementation must cover the body with its own full-attempt deadline and byte limit, including missing/false Content-Length and slow/chunked responses. Preserve conservative reservations on ambiguous failures.
- [Microsoft AllowAutoRedirect](https://learn.microsoft.com/en-us/dotnet/api/system.net.http.httpclienthandler.allowautoredirect) defaults true and only clears Authorization on redirects, not other headers. Gemini supplies x-goog-api-key as a custom header. Task7 should explicitly disable automatic provider redirects (and hidden retries) or prove each allowed actual attempt is separately reserved; disabling is the simpler bounded approach. This is a source/default-behavior risk, not evidence of an observed live redirect or key leak.
- Verified operation names in WordAiService: analyze-word, word-detail, review-translation, extract-words; batch also calls word-detail. Keep all covered, including cache-hit zero-provider cases.
- Naming clarification from WordAiService.Batch.cs: the current "batch" partial combines primary and secondary translations for one word; it is not a multi-word fan-out endpoint. Four current AI routes exist on account/device controllers. Existing resource filters consume one allowed HTTP-operation quota before service cache lookup (free guest or shared account); provider fallback and service cache hits therefore have different accounting from that quota. User-facing D2 explanations must not equate one quota request to exactly one new card or one paid provider attempt. Reading already saved local content is separate. No D2 policy change was made by this inspection.

## Transport retry source check
The official [.NET 10.0.12 pool source](https://raw.githubusercontent.com/dotnet/runtime/v10.0.12/src/libraries/System.Net.Http/src/System/Net/Http/SocketsHttpHandler/ConnectionPool/HttpConnectionPool.cs) has internal connection-failure, protocol-downgrade and HTTP/2 stream-limit retry paths. No Polly registration is therefore insufficient evidence of one wire attempt. Local .NET 10.0.12 is installed; the Dockerfile uses floating aspnet:10.0, so this is not verification of a deployed runtime.

In the pinned [HTTP/1 connection source](https://raw.githubusercontent.com/dotnet/runtime/v10.0.12/src/libraries/System.Net.Http/src/System/Net/Http/SocketsHttpHandler/HttpConnection.cs), retry starts false. EOF permits retry when content is null or an Expect-Continue operation remains pending; ordinary non-null POST content without Expect-Continue does not take that branch.

Implementation candidate, still requiring tests: explicitly constrain provider requests to HTTP/1.1 exact, non-null JSON content, ExpectContinue=false, no redirects, proxy or automatic credentials, and no retry handler. Validate the actual configured handler using a loopback server that reads the POST then disconnects, counts submissions, and covers redirects plus body deadlines. Fake handler tests alone cannot establish transport retry behavior. Preserve ambiguous reservations. Do not claim pooling settings alone eliminate retries or assume provider-side idempotency. Record runtime upgrade/revalidation limits; do not change unrelated runtime versions in this task.

## Usage schema refresh during Task10 review
Official OpenAI docs fetched through the docs connector confirm `usage.input_tokens_details.cache_write_tokens` as well as `cached_tokens`. The [prompt-caching guide](https://developers.openai.com/api/docs/guides/prompt-caching#monitor-cache-performance) calculates ordinary input as total input minus cache reads minus cache writes. These are alternative rates, not additive charges on the same token. Validate nonnegative consistent components before releasing any reservation; missing components must not silently become an underpriced estimate. The guide also documents explicit cache mode with no breakpoints as disabling cache writes, but changing caching is an implementation choice, not a requirement to remove the current optimization.

The [Responses create reference](https://developers.openai.com/api/reference/cli/resources/responses/methods/create) identifies `service_tier=default` as Standard, omitted/auto as project-selected, and fast/priority as Fast mode (returned as priority). Returned processing tier can differ from requested tier. Check the actual returned model/tier before settlement; retain a conservative reserve for unknown/mismatched metadata.
