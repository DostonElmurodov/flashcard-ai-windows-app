## Minimal data contract

Keep the existing server-resolved device-word library namespace (`DeviceUuid`, now assigned by the server under2B) and its private-data boundary. Do not replace it with quota subject, purchase owner, linked account ID or another phone's library. Same-key resume keeps this namespace. A new installation's own restored local library may synchronize through its own namespace; it gains no ability to inspect/overwrite another phone/account's content from a mobile grant. No new Library table or cross-device active-word-cap union.

Add to `DeviceWordEntity`: nullable `double ClientCreatedAtSeconds` and `bool RetainedMetadataOnly=false`; add `DeviceEntity.WordInventoryRevision` long default0 for the server-owned library. Existing rows keep all payload/CreatedAt/IDs; no guessed creation time. Client word IDs are exact ordinal strings within this library. Change the semantic unique index to nonunique; add unique `(DeviceUuid,ClientWordId)` for non-null client IDs after conflict inventory. A caller supplying ClientWordId must never fall back to another saved row merely because normalized text/languages match. Legacy ID-less AI reservation placeholders remain separately counted and may be claimed only by an explicit successful save matching that placeholder's identity; do not collapse two saved IDs into it. A no-ID legacy request remains compatible only where it cannot ambiguously acknowledge/delete a saved ID.

Extend existing `DeviceWordUpsertRequest`/Swift DTO with optional trailing `ClientCreatedAtSeconds` (Swift `Double?`). New iOS sends its exact SQLite REAL creation time. Once a row receives client creation metadata, it is immutable; changing it returns409 `word_order_conflict`. Compare finite IEEE754 values identically to SQLite, then ClientWordId using ordinal/C collation. Never substitute server arrival time, random row ID or locale comparison. Validate finite timestamp and bounded ID string (existing client ID size conventions); old missing metadata stays unknown, not zero.

Existing rows need a metadata-only reconciliation path because submitting their changed text to learn eligibility would be circular. Add `POST /owlai/device-words/order` with the existing device JWT + exact raw-body assertion, body limit256,000 bytes, at most500 entries:

```text
DeviceWordOrderRequest(long BaseRevision, DeviceWordOrderEntry[] Words)
DeviceWordOrderEntry(string ClientWordId, double CreatedAtSeconds,
  string NormalizedWord, string NativeLanguage, string LearningLanguage)
DeviceWordOrderResponse(long Revision, bool IsComplete, string[] EligibleClientWordIds,
  int ActiveWordCount, int FreeLimit)
```

`DeviceWordService.ReconcileOrderAsync(string serverLibraryUuid, DeviceWordOrderRequest request, CancellationToken ct): Task<DeviceWordOrderResponse>` uses the existing transaction-scoped per-library word lock, READ COMMITTED reread and server clock. No library/owner/account/quota ID in body. Reject duplicate client IDs or conflicting creation metadata atomically. Require BaseRevision to equal the locked library revision before any metadata creation/change; mismatch409 `word_order_conflict` with no mutation. Increment that revision on every actual order/upsert/delete/reservation mutation. An exact all-rows-already-identical retry is an acknowledgment with current revision, not a repeated mutation. This prevents a delayed order batch from recreating a just-deleted row. The client fetches current revision and regenerates from current local IDs after a conflict, never blindly replays a deleted snapshot.

Update exact known rows' missing creation metadata without changing payload. An unknown locally saved ID can create a **metadata-only retained row** (ClientWordId/order/normalized/languages, no translation/detail); it grants no paid history/AI/content-write authority. This preserves two client IDs that an old semantic row may have collapsed. Omitted rows are never deleted and active legacy payloads are never silently overwritten. This does not invent a permanent device-cloud deletion history or replace AccountSync's existing tombstones.

Metadata-only rows may record a retained library larger than ten; that is preservation bookkeeping, not permission to add/edit an eleventh word. The first ten eligible IDs alone may receive content under true-free access. A normal new add still uses the existing aggregate count across this library's languages and collections and cannot bypass the cap by submitting order metadata first: a metadata-only row outside first ten remains locked and rejected. A row's metadata cannot claim WasEverPaid or an account owner. RetainedMetadataOnly changes to false only after an authorized exact content save; no payload is replaced by metadata upload.

After each batch return first-ten eligible IDs only when the library's relevant active retained rows have exact client IDs/order (`IsComplete=true`); otherwise return IsComplete=false and no authoritative eligible set. Repeated identical batches are idempotent. Add `GET /owlai/device-words/order` with existing device proof and the same response so client can obtain final eligibility after all batches. No foreign-library IDs are returned. An unmatched legacy active reservation or ambiguous old ClientWordId must be reported/reconciled deliberately; do not invent chronological order to report completion.

For true-free libraries with at most ten known active rows, existing content checks can preserve compatible behavior while metadata fills in. With more than ten, content-changing free upsert/AI of an existing word must require complete ordering and exact identity within first ten. Incomplete ordering:409 `word_order_reconciliation_required`, no mutation/quota/provider. Out-of-ten:402 with existing `accepted:false` save contract (AI route returns paid-access denial before provider); preserve user text/pending state. Exact no-change acknowledgment and deletion remain allowed outside the ten or under inactive subscription. Expired paid retains accepted read/review/delete/export, never new content/AI.

Deletion targets exact `(server library,ClientWordId)` and cannot fall back to matching another ID's normalized text. If only old semantic identity is supplied and more than one saved row matches, return409 `word_identity_ambiguous` with no deletion. Preserve the existing queued mutation ordering and successful-identity acknowledgment fields in iOS. For old collapsed rows, use exact existing ClientWordId plus the local metadata/payload; never copy one server translation into the other saved card as if proven identical.

## Client and storage boundaries

iOS uploads local IDs/order in batches before reconciling a true-free retained library with more than ten. `WordRepository` keeps original created_at/id, text, review state, ownership metadata and pending mutations. It uses the server eligible set for server-backed changes once complete; its local offline order uses the same tuple. Late metadata/save responses use existing mutation generation/identity safeguards and cannot acknowledge another word. Backend acceptance, local save denial markers and retries retain Task8 semantics.

AccountSync keeps existing ownership, max10000 storage/history capacity, cursors, versions, conflicts, tombstones, review data, pending offline payloads and exact retries. Do not reduce its storage to ten records or add broad commercial write gating here. Windows accepted local policy remains once per its authenticated saved library/all languages; verify its timestamp/id convention only if a touched shared-sync boundary requires it. No hidden cross-account or cross-phone library aggregation.
